# Sprint 1 Retrospective — 30 October 2026

**Project:** Book Club Library  
**Participants:** Daniel, Gowtami, Robert, Giorgi  
**Scrum Master:** Giorgi

## What went well

- The team collaborated and made progress on the application foundation and individual features.
- More challenging tasks were broken down into smaller, manageable pieces as needed.
- The initial GitHub Project access issue was identified and resolved.

## Challenges and observations

- **Project access:** Some members initially couldn't update the GitHub Project board, which caused confusion. This was resolved.
- **Task complexity:** As a learning project, some tasks proved more challenging than initially expected.
- **Acceptance criteria:** More detailed acceptance criteria could make implementation easier to follow. However, defining everything in advance would require additional planning time, especially when requirements or technical details are not yet clear.
- **Code reviews:** Reviews took more time than anticipated. Some minor issues could have been caught through self-review before opening PRs.
- **Time management:** Exploring testing approaches and improving test coverage sometimes took time away from implementing core functionality.

No major unresolved blockers were identified.

## Improvements for Sprint 2

1. **Review our own code before requesting PR reviews.** Check for obvious mistakes, run relevant tests, and use tools such as the Ruff VS Code extension to catch common issues.
2. **Refine acceptance criteria when needed.** Start with clear essential criteria and add detail as implementation reveals new requirements or edge cases, with team agreement.
3. **Prioritize core functionality and integration.** Maintain essential test coverage, but avoid spending disproportionate time exploring additional testing approaches when critical features remain unfinished.
4. **Allow time for peer reviews.** Account for review and correction time when planning work, rather than treating implementation as the final step.

## Conclusion

Sprint 1 provided useful experience in coordinating development, managing dependencies, and reviewing code. For Sprint 2, the team aims to improve efficiency through earlier self-review, clearer task requirements, and stronger prioritization of working, integrated functionality.
